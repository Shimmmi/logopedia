## 1. Система личного кабинета

### 1.1 Способы регистрации и входа

Основной способ — email + пароль. Дополнительно — вход через российские сервисы идентификации (без использования Google/Apple OAuth, заблокированных или нежелательных для использования в РФ-сегменте).

| Способ входа | Технология | Примечание |
|---|---|---|
| Email + пароль | Собственная система, bcrypt/argon2 | Основной способ, обязателен всегда |
| Госуслуги (ESIA) | OAuth 2.0 через api.gosuslugi.ru (ЕСИА) | Требует регистрации ИС в Минцифры/ЕСИА, юридическое лицо |
| VK ID | OAuth 2.0, vkid.dev | Быстрая интеграция, популярно в РФ |
| Яндекс ID | OAuth 2.0, id.yandex.ru | Простая интеграция, привычно пользователям |
| Mail.ru ID | OAuth 2.0 (VK Connect) | Опционально, для охвата аудитории |

**Примечание по ЕСИА:** интеграция с Госуслугами требует прохождения аккредитации как информационной системы, подключения по 63-ФЗ/149-ФЗ и оформления юрлица/ИП — закладывается как этап 2, после MVP. На старте реализуются email и VK ID / Яндекс ID (наиболее быстрые для внедрения).

### 1.2 Сценарий регистрации по email

1. Пользователь вводит email, пароль (мин. 8 символов, спецсимвол+цифра), ФИО, название учреждения
2. Отправляется письмо с кодом подтверждения (6 цифр, TTL 15 минут) через российский SMTP-сервис (Yandex 360 / Mail.ru для бизнеса / Unisender — без Gmail/SendGrid)
3. Подтверждение email → активация аккаунта → онбординг (короткий тур по интерфейсу)
4. Согласие с политикой обработки персональных данных (152-ФЗ) — обязательный чекбокс при регистрации

### 1.3 Восстановление доступа

- Восстановление пароля по email (ссылка с одноразовым токеном, TTL 1 час)
- Резервный email для критичных уведомлений (опционально)
- Возможность подключения 2FA (TOTP через приложение-аутентификатор) — рекомендуется для premium-аккаунтов

### 1.4 Профиль пользователя

- ФИО, должность, учреждение, контактный телефон, фото
- Настройки уведомлений (email / push / отключить)
- Тарифный план (Free / Pro / Premium) и история платежей
- Экспорт всех своих данных (в рамках 152-ФЗ — право на выгрузку)
- Удаление аккаунта с полным удалением персональных данных по запросу

### 1.5 Роли и права доступа

| Роль | Права |
|---|---|
| Логопед (основная роль) | Полный доступ к своим ученикам, расписанию, документам, ИИ-модулям |
| Администратор школы (опционально, v2.1) | Просмотр расписаний нескольких логопедов, управление кабинетами, без доступа к персональным медицинским данным |
| Ассистент/стажёр (опционально) | Ограниченный доступ по приглашению основного логопеда |

## 2. Система составления расписания

Реализуется по лучшим практикам сервисов бронирования и CRM для частных специалистов (аналоги: Yclients, Alteg.io, Google Calendar + Calendly-логика). Цель — избавить логопеда от ручного ведения журнала и Excel-таблиц.

### 2.1 Календарь занятий

- Виды отображения: День / Неделя / Месяц / Список (Agenda)
- Drag-and-drop перенос занятий мышью
- Цветовая кодировка по типу занятия (диагностика / индивидуальное / групповое / консультация)
- Быстрое создание занятия кликом по слоту календаря
- Привязка занятия к ученику из картотеки (автоподстановка ФИО, диагноза, тегов)
- Групповые занятия — привязка нескольких учеников к одному слоту

### 2.2 Повторяющиеся события (recurring)

- Настройка регулярности: еженедельно / 2 раза в неделю / по дням недели (например, Пн, Ср, Пт)
- Автоматическое создание серии занятий на учебную четверть/год с учётом каникул и праздников РФ (интеграция с производственным календарём)
- Возможность разово отменить/перенести одно занятие из серии без разрушения всей серии (модель RRULE, как в iCalendar/Google Calendar)

### 2.3 Управление конфликтами и загрузкой

- Автоматическая проверка пересечения времени (конфликт слотов)
- Визуальное предупреждение при попытке поставить два занятия на одно время
- Настройка рабочих часов и перерывов логопеда (нельзя создать занятие вне рабочего окна)
- Буферное время между занятиями (например, 5–10 минут на переход/отдых)

### 2.4 Уведомления и напоминания

- Напоминание логопеду о занятии за 30/60 минут (push / email)
- Автоматическое уведомление об отменённом/перенесённом занятии
- Сводка на день/неделю — отправляется утром по расписанию (email-дайджест)
- Опционально: SMS-уведомления родителям через российский SMS-шлюз (SMS Aero, SMSC.ru) — для premium

### 2.5 Аналитика и отчётность по расписанию

- Статистика: количество проведённых/отменённых занятий за период
- Автоматический учёт факта проведения занятия (чекбокс «Занятие проведено» / «Отменено» / «Ученик отсутствовал» — причина)
- Автогенерация отчёта о посещаемости и нагрузке за четверть/год (для администрации школы) — экспорт в DOCX/XLSX
- Расчёт фактической нагрузки в часах для тарификации/отчётности логопеда

### 2.6 Дополнительные возможности планировщика

- Экспорт расписания в формате .ics (импорт в Google Calendar, Яндекс.Календарь, Outlook)
- Виджет «Ближайшее занятие» на главной странице личного кабинета
- Список ожидания (waitlist) — если слот занят, ученик/логопед может встать в очередь
- Быстрый переход из карточки занятия в модуль «Задания» или «Заключение» по конкретному ученику

### 2.7 Технические детали реализации

| Компонент | Технология |
|---|---|
| Календарный UI | FullCalendar.js (React-обёртка) или react-big-calendar |
| Хранение повторов | RRULE (rrule.js) — стандарт iCalendar для регулярных событий |
| Таблица БД | schedule_events: id, pupil_id(s), user_id, start_at, end_at, rrule, type, status, notes |
| Фоновые задачи | node-cron / BullMQ + Redis — для отправки напоминаний по расписанию |
| Производственный календарь РФ | API xmlcalendar.ru или встроенный JSON-справочник праздников/переносов |

## 3. Система хранения документации логопеда

Личное файловое хранилище логопеда — отдельно от документов, привязанных к конкретным ученикам (для нормативных документов, шаблонов, методических материалов, отчётов для администрации и т.д.).

### 3.1 Структура хранения

- Иерархия папок, создаваемых пользователем произвольно (как в облачном диске)
- Предустановленные системные папки: «Рабочие программы», «Заключения», «Диагностика», «Отчётность», «Методические материалы», «Шаблоны», «Прочее»
- Возможность перемещения файлов между папками (drag-and-drop)
- Вложенные подпапки без ограничения глубины (разумный лимит — 5 уровней)

### 3.2 Классификация и теги документов

- Система тегов для файлов (независимо от папок): #годовой-отчёт, #шаблон, #приказ, #протокол-ПМПК и т.д.
- Автоматическая классификация — при генерации через ИИ-модули документ сразу получает системный тег (auto: заключение / программа / задания / диагностика)
- Фильтрация по: типу файла (docx/pdf/аудио/изображение), тегам, дате создания, привязанному ученику
- Полнотекстовый поиск по названию и содержимому документов (для docx/pdf — индексация текста через pg_trgm или Elasticsearch/Meilisearch)

### 3.3 Версионность и история

- При повторной генерации/редактировании документа — сохранение предыдущей версии (история версий, откат)
- Журнал действий: кто, когда создал/изменил/удалил документ
- Корзина с возможностью восстановления удалённых файлов (хранение 30 дней)

### 3.4 Технические требования к хранилищу

| Параметр | Решение |
|---|---|
| Файловое хранилище | Локальная ФС VPS (/var/www/logoped/storage) на старте; MinIO (S3-совместимое, self-hosted) при росте объёма |
| Лимиты по тарифу | Free — 500 МБ, Pro — 5 ГБ, Premium — 25 ГБ на аккаунт |
| Форматы | docx, pdf, xlsx, jpg/png, mp3/wav/m4a (аудиозаписи занятий) |
| Безопасность | Доступ к файлам только по подписанным временным URL (signed URL), проверка владельца на бэкенде |
| Антивирусная проверка | ClamAV при загрузке файлов (базовая защита сервера) |

## 4. Расширенная картотека учеников

### 4.1 Карточка ученика — полная структура

| Блок карточки | Поля |
|---|---|
| Основные данные | ФИО, фото (опц.), дата рождения, пол, школа, класс, дата зачисления на сопровождение |
| Контакты | ФИО родителя/законного представителя, телефон, email, согласие на обработку ПД (файл/чекбокс с датой) |
| Диагностический статус | Актуальный диагноз, статус ПМПК (дата, номер заключения), рекомендованный вариант АОП |
| Теги | Множественный выбор + добавление своих (см. 4.2) |
| История занятий | Автоматическая лента из модуля «Расписание»: дата, тема, статус посещения |
| Документы ученика | Все привязанные файлы: диагностика, заключения, программы, задания |
| Медиафайлы | Аудиозаписи занятий, фото рабочих материалов |
| Динамика/прогресс | Заметки логопеда по датам + визуализация прогресса (график по направлениям коррекции) |
| Статус сопровождения | Активный / Приостановлен / Выпущен / Архив |

### 4.2 Система тегов

Гибкая тег-система для быстрой сегментации учеников. Теги делятся на категории (цветовая кодировка):

| Категория тегов | Примеры | Цвет |
|---|---|---|
| Диагноз/нозология | ТНР, ЗПР, УО, РАС, ОНР I/II/III ур., ФФНР | Красный |
| Направление работы | Постановка [Р], автоматизация [Ш], дисграфия, дислексия, ЗРР | Синий |
| Организационные | Группа, индивидуально, ПМПК пройдено, ПМПК ожидается | Жёлтый |
| Свои теги логопеда | Любые произвольные, создаваемые пользователем | Серый (по умолчанию) |

- Автозаполнение существующих тегов при вводе (autocomplete, без дублей)
- Массовое присвоение тегов нескольким ученикам сразу
- Клик по тегу в любом месте интерфейса → список всех учеников с этим тегом

### 4.3 Сортировка и фильтрация

- Сортировка: по алфавиту, по дате зачисления, по классу, по дате последнего занятия
- Фильтры: по тегам (мультивыбор с логикой И/ИЛИ), по классу/школе, по статусу сопровождения, по наличию непроверенных документов
- Быстрый поиск по ФИО (fuzzy search — устойчивый к опечаткам)
- Сохранённые фильтры («Мои виды» — например, «Только ТНР 1 класс»)
- Режимы отображения картотеки: таблица / карточки (grid) / компактный список

### 4.4 Вложения в карточке ученика

- Загрузка документов: перетаскивание файлов (drag-and-drop) прямо в карточку
- Поддержка форматов: docx, pdf, jpg/png (сканы), mp3/wav/m4a (аудиозаписи занятий)
- Запись аудио прямо из браузера (Web Audio API / MediaRecorder) — кнопка «Записать занятие»
- Автоматическая привязка сгенерированных ИИ-документов (заключение, программа, задания) к карточке ученика
- Просмотр PDF/изображений без скачивания (inline-viewer), плеер для аудио прямо в карточке

### 4.5 Родительский доступ (опционально, v2.1)

- Логопед может выдать родителю ограниченную ссылку/доступ: расписание занятий ребёнка, домашние задания, общий прогресс — без доступа к полному заключению

## 5. Система ИИ-анализа документов и аудиозаписей

### 5.1 Общая логика уровней доступа

| Тариф | Модель для анализа | Возможности |
|---|---|---|
| Free | Базовая модель через OpenRouter (напр. Gemini Flash / GPT-4o-mini) | Анализ текстовых документов, простая транскрипция коротких аудио (до 3 мин) |
| Pro | Базовая модель, увеличенные лимиты | До 20 анализов документов/мес, аудио до 15 мин, история анализов |
| Premium | Продвинутая модель (напр. GPT-4o / Claude Sonnet / Gemini Pro) + Whisper Large для аудио | Безлимитный анализ, углублённый разбор аудио с оценкой звукопроизношения, сравнение динамики по датам |

Переключение модели реализуется на бэкенде параметром `model` в запросе к OpenRouter — тарифная логика не меняет код, только конфигурацию пользователя.

### 5.2 Анализ документов

- Загрузка стороннего документа (например, заключение ПМПК, справка невролога, старая рабочая программа) → извлечение текста (pdf-parse / mammoth для docx, OCR через Tesseract для сканов)
- ИИ выделяет ключевые факты: диагноз, рекомендации специалистов, значимые для работы логопеда моменты
- Автоматическое предложение тегов для карточки ученика на основе анализа документа
- Сравнение двух заключений (например, начало и конец года) — ИИ формирует сводку динамики
- Проверка рабочей программы на соответствие требованиям ФГОС/ФАОП (сверка структуры по чек-листу)

### 5.3 Анализ аудиозаписей занятий

- Транскрибация аудио в текст (базовый уровень: Whisper через OpenRouter/сторонний API; продвинутый: Whisper Large v3 / Yandex SpeechKit для качественной русскоязычной транскрибации)
- ИИ формирует краткое резюме занятия: какие задания выполнялись, реакция ребёнка, трудности
- Premium: анализ звукопроизношения — выявление в транскрипте характерных замен/искажений звуков, требующих внимания
- Автоматическое предложение внести резюме занятия в карточку ученика (в блок «Динамика»)
- Хранение аудио привязано к конкретному занятию из расписания (модуль 2) и карточке ученика (модуль 4)

### 5.4 Технические детали ИИ-модуля

| Компонент | Реализация |
|---|---|
| Оркестрация запросов | Единый backend-сервис /api/ai/* с выбором модели по тарифу пользователя |
| Транскрибация аудио | OpenRouter (Whisper) базово; Yandex SpeechKit STT как альтернатива для лучшего распознавания русской речи |
| Очередь обработки | Redis + BullMQ — анализ аудио/больших документов выполняется асинхронно, пользователь получает уведомление по готовности |
| Ограничение затрат | Подсчёт токенов/минут на пользователя в БД (таблица ai_usage), контроль лимитов тарифа перед вызовом API |
| Хранение результатов | Таблица ai_analyses: id, source_type(doc/audio), source_id, model_used, result_json, created_at |

## 6. QoL-функции (предложения для улучшения продукта)

Дополнительные функции, повышающие удобство ежедневной работы логопеда — рекомендуется реализовывать поэтапно после MVP.

### 6.1 Библиотека шаблонов и материалов

- Готовая база речевого материала (чистоговорки, скороговорки, тексты) с фильтром по звуку и возрасту
- Возможность сохранять свои сгенерированные ИИ-задания в личную библиотеку для повторного использования
- Обмен шаблонами между логопедами (опционально — «сообщество», модерация)

### 6.2 Быстрый ввод и заметки

- Голосовой ввод заметок прямо в браузере (Web Speech API) — надиктовать наблюдение вместо набора текста
- Быстрые заметки «на лету» во время занятия (виджет поверх карточки ученика, без перехода на другую страницу)
- Горячие клавиши для частых действий (новое занятие, новая заметка, поиск ученика)

### 6.3 Автоматизация отчётности

- Автогенерация ежемесячного/ежегодного отчёта логопеда для администрации (сводка по всем ученикам, часам, документам)
- Автонапоминание о приближающемся сроке повторной диагностики/ПМПК по каждому ученику
- Чек-лист обязательной документации на ученика с индикатором заполненности (сколько документов не хватает)

### 6.4 Визуализация прогресса

- Дашборд прогресса ребёнка — графики по направлениям коррекции (звукопроизношение, лексика, грамматика и т.д.) по датам
- Наглядная шкала «до / после» на основе сравнения диагностических срезов
- Общая статистика логопеда: сколько детей выпущено, средняя длительность сопровождения, самые частые нарушения

### 6.5 Мобильность и доступность

- PWA (Progressive Web App) — установка сайта как приложения на телефон, работа офлайн с синхронизацией
- Тёмная тема интерфейса
- Адаптация под слабовидящих (увеличенный шрифт, контрастная тема) — актуально с учётом специфики аудитории

### 6.6 Совместная работа (для школ с несколькими логопедами)

- Общая база методических материалов учреждения
- Передача ученика другому логопеду с сохранением истории (при переводе/смене специалиста)
- Календарь отпусков/больничных с автопереносом занятий

### 6.7 Прочее

- Автосохранение черновиков форм (чтобы не терять данные при случайном закрытии вкладки)
- Уведомление о завершении генерации ИИ-документа, если пользователь ушёл со страницы (push-уведомление браузера)
- Чек-лист «Первые шаги» при регистрации — онбординг новых пользователей
- Обратная связь / багрепорт прямо из интерфейса (виджет в углу экрана)

## 7. Обновлённая схема базы данных

Дополняет базовые таблицы из ТЗ v1.0 (`users`, `pupils`, `diagnostics`, `programs`, `conclusions`, `tasks`) новыми сущностями:

**auth_identities** — привязка внешних OAuth-аккаунтов
- `id, user_id (FK), provider (email/vk/yandex/esia), provider_uid, created_at`

**schedule_events** — занятия расписания
- `id, user_id (FK), pupil_ids (массив/M2M), start_at, end_at, rrule, type, status, notes, created_at`

**documents** — личное хранилище логопеда
- `id, user_id (FK), folder_id (FK, nullable), pupil_id (FK, nullable), file_path, file_type, tags (массив), version, created_at`

**folders** — папки хранилища
- `id, user_id (FK), parent_id (FK, nullable), name, created_at`

**pupil_tags / tags** — система тегов учеников
- `tags: id, user_id (FK), name, category, color`
- `pupil_tags: pupil_id (FK), tag_id (FK)` — связь многие-ко-многим

**pupil_attachments** — вложения в карточке ученика
- `id, pupil_id (FK), file_path, file_type (doc/audio/image), linked_event_id (FK, nullable), created_at`

**ai_analyses** — результаты ИИ-анализа
- `id, user_id (FK), source_type, source_id, model_used, result_json, created_at`

**ai_usage** — учёт лимитов ИИ по тарифу
- `id, user_id (FK), period (месяц), tokens_used, audio_minutes_used`

**subscriptions** — тарифы
- `id, user_id (FK), plan (free/pro/premium), status, current_period_end, payment_provider`

## 9. Правовые требования (152-ФЗ)

Сервис обрабатывает персональные данные несовершеннолетних (специальная категория данных — сведения о здоровье), что требует повышенного внимания к комплаенсу:

- Согласие законного представителя ребёнка на обработку персональных данных — обязательный документ, прикрепляемый в карточку ученика
- Хранение персональных данных граждан РФ исключительно на серверах, расположенных на территории РФ (условие уже выполнено — VPS CloudCore.ru)
- Публикация Политики обработки персональных данных и Пользовательского соглашения на сайте (юридически значимые документы)
- Шифрование чувствительных данных в БД (данные о диагнозах — на уровне столбцов, at rest encryption)
- Уведомление Роскомнадзора об обработке персональных данных (обязанность оператора ПД — юридический, не технический этап)
- Логирование доступа к медицинским/диагностическим данным (кто и когда открывал карточку ученика)
- Право пользователя и родителя на удаление данных ребёнка по запросу
